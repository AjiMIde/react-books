# React Router v6 完善配置

* 还记得我们的目标吗？

> * 大部分情况下，服务器都只提供`hash`路由模式（而非`history`）
> * 最终配置需要达到：**路由嵌套**，**按需引入**，**动态路由**，**路由守卫**，**路由传参**
> * **路由懒加载**，**404页面**，**重定向**，**权限控制**等功能

## 现成实例

* 你可以在本例中`template/router`中拿到一个最佳示例

## 挑选路由:数据路由

* 尽管`history`模式是被推荐的，好处也显而易见，但`hash`模式不得不选
* 数据路由必选（并不知道`router v5`是以什么形式组织路由的，但现在提供了`createRoutesFromElements`来快速生成数据路由）
* `RouterProvider`为支撑数据路由提供了容器
* 数据路由能更方便地管理路由，做权限判断等

## 按需引入

* 按需引入能减少打包体积，提高加载速度，这几乎是必须的
* 使用`React.lazy`只是其中一种方式

```tsx
const r = [
  {
    path: '/lazy',
    // 这种要求组件 lazy export function Component 来实现
    lazy: () => import('@/apps/Lazy')
  },
  {
    path: '/lazy-component',
    // 这种只需要正常 export default
    Component: React.lazy(() => import('@/apps/LazyComponent')),
  },
  {
    path: '/lazy-use-react-lazy',
    // 这种则需要
    element: <LazyUseReactLzay />
  },
]
```

## Route对象配置

* 我们只挑重点的说，其他的请看[官方doc](https://reactrouter.com/en/main/route/route#type-declaration)

```tsx
import boolean from 'async-validator/dist-types/validator/boolean';

const route = {
  path: '',         // 注意 :id/:name 等参数路由的匹配，并用 useParams() 使用 或 loader (paramrs) => {} 使用
  index: boolean,   // true/false，通常用于嵌套路由中，如以下的 routeIndex
  chilren: '',
  loader: () => {},   // 请看文档
  action: () => {},   // 如上
  element: <></>,     // 这两个2选1，其中，element用于<Route>路由，而Component用于数据路由，强行调用，会引起性能问题
  Component: Home,
  errorElement: <></>,              // 错误抛出时显示的组件
  ErrorBoundary: ErrorX,            // 同上
  lazy: () => import('@/app/page')  // 比较有趣，请看 lazy 模块
  // ...
  
}

const routeIndex = {
  path: '/home',
  element: <Home />,
  chilren: [
    { 
      index: true,            // index: true 的作用跟 path: '' 相当
      element: <HomeIndex />  // 当匹配到 /home ，显示为： <Home /><HomeIndex />
    },
    {
      path: '/about',
      element: <About />      // 当匹配到 /home/about ，显示为： <Home /><About />
    }
  ]
}
```

## router lazy

* `lazy`配置比较有趣，不同于`React.lazy`，`lazy`配置需要`import('somePage')`如下：
* 而不能`export default`，如下的配置，都是一个正常的`route`配置内容

```ts
export function loader (rest) {}
export function Component () {}       // 必须
export function ErrorBoundary () {}
export function action () {}
```

* 此外还有这种更高级的玩法，请自行研究
 
```ts
const route = {
  async lazy () {
    const { Index } = await import("./pages/Dashboard");
    return {Component: Index};
  },
}
```

## loader & action

* 如果你简单阅读过文档，就会发现此 `loader & action` 两个路由函数配置，它们主要用于在`route jump`时一些加载数据或操作；
* 并且，更多出现在`form.submit`等场景下？建议查看其他文档。

## Component vs element

* 可以通过`Component`和`element`来指定组件
* `element`相对来讲性能更好，能直接传递`props参数`
* `Component`则更加灵活，动态，需要通过函数传参
* 通常会使用`Component`，更加灵活、拓展性高

```js
// 使用 element
const routes = [
  {
    path: '/',
    element: <HomePage />,
  },
];

// 使用 Component
const routes = [
  {
    path: '/',
    Component: HomePage,
  },
];
```

## 导航`NavLink/Link/a`

* `NavLink/Link/a` 这三个标签都可以用来导航

```tsx
function App () {
  return (<div>
    // 可以将 style 换成 className
    <NavLink style={({ isActive, isPending }) => ({
        color: isActive ? 'red' : 'black',
      })} to={}>
    </NavLink>
    
    // link 支持相对、绝对等导航
    <Link to={'./'} />
  </div>)
}
```

## Suspense

* 通常用于`lazy`加载，会触发`Suspense`，并显示`loading`组件
* 大部分情况下，如果不配置`suspense`，会引起某些显示错误！

```tsx
export default function DataRouter () {
  return (<Suspense fallback={<div>loading...</div>}>
    <HashRouter>
      <MyRouter />
    </HashRouter>
  </Suspense>)
}
```
